# 需求說明

## 這是什麼
一個在我自己電腦上執行的 Discord agent。只要它開著，我 Discord Server 裡指定頻道的任何人傳一張票券照片（或 PDF 電子票券）進來，它就會判斷、讀出票券資訊、建檔，再回覆上傳者。agent 關掉就不處理，重開後也不補處理關掉期間傳的照片。

任何種類的票券都收（演唱會、電影、高鐵、機票、展覽……），票券種類由 agent 自己判斷。

## 誰會用
我自己的 Discord Server 裡、那個指定頻道的任何人，用手機或電腦都可以傳。

## 使用的流程
1. 有人在頻道裡傳一張票券照片
2. agent 收到，先回一個「處理中」的提示
3. agent 判斷：是不是票券、票券種類、名稱、日期時間、地點、座位或票種、金額與幣別
4. agent 把結果記下來、把照片存起來
5. agent 回覆上傳者這張票券的結果，並附上「上傳者自己」的當月與歷史累計（筆數與金額，金額依幣別分開顯示）

## 要記錄的內容（存成一個可以一直往下加的 Excel 檔）
一個檔、兩張工作表：「紀錄」（明細）和「統計」（每位上傳者的累計）。

「紀錄」的欄位：
- 流水號
- 記錄時間（收到照片的時間）
- 上傳者
- 票券種類
- 名稱（活動、電影或班次名稱）
- 日期時間（票面上的場次或出發時間）
- 地點（場館、影城或起訖站）
- 座位或票種
- 金額
- 幣別
- 其他資訊（票號、場次、備註等；一張照片有多張票時註明張數）
- 照片存放位置
- 狀態（有效／已刪除／已更正移除）
- 上傳者ID
- 回覆訊息ID
- 照片SHA256（照片原始位元組的雜湊，防止同一張照片被重複記錄；補齊既有紀錄時有多個，新的在前）

票面上看不到的欄位留空。一張照片記成一筆；照片裡有多張票時，金額記總價。

照片另外存進一個資料夾，檔名用「日期時間 + 票券名稱簡稱」。

## 回覆內容
- 收到時先有「處理中」的提示
- 處理完回覆：票券種類、名稱、日期時間、地點、座位或票種、金額與幣別，並附上上傳者自己的當月與歷史累計
- 回覆與查詢**不顯示票號**（票號只存在 Excel 的「其他資訊」）
- 看不清楚的欄位留空，並在回覆裡提醒上傳者可以重傳清楚的照片

## 特殊情況
- **不是票券**：回覆「你傳的不是票券，是某某東西」，照片存起來，**不寫進 Excel**。
- **照片模糊**：照樣建檔，讀不到的欄位留空，回覆提醒。
- **重複上傳同一張票券**（同一位上傳者）：不新增，用新資料補齊原本那一筆，兩張照片都保留。
- **完全相同的照片再傳一次**（同一位上傳者、舊紀錄狀態為「有效」）：用照片的 SHA-256 認出，直接回覆「這張照片先前已記錄過 #N，沒有新增」。不重新辨識、不新增紀錄、不保存重複照片，累計不增加；回覆那則訊息仍可更正。舊紀錄若已刪除或已更正移除，重傳同一張照片會建立新紀錄。不是票券、處理失敗的照片不在這個規則內。只認位元組完全相同的照片；舊紀錄不會補算雜湊。
- **處理失敗**：自動重試最多 2 次，仍失敗就回覆「處理失敗，請稍後再試」；照片存起來，不寫進 Excel；原因寫進 log。
- **附件不是支援的格式或太大**：回覆提示（支援 JPG、PNG、WebP、PDF，每個檔案 10 MB 以內）。純聊天文字不理。PDF 只處理第一頁。
- **傳太快**：同一個人每分鐘最多 8 次（每張照片算一次，更正與有效的指令也各算一次），超過的回覆「傳太快了，請稍後再試」。

## 舊 Excel 檔
加入「照片SHA256」欄之前建立的 Excel（15 欄）可以直接使用：agent 啟動時只會補上新欄位的標題，舊紀錄一列都不動（會先留一份備份）。欄位對不上的檔案仍然拒絕啟動。

## 更正與指令
- **打字更正**：上傳者回覆 bot 的結果訊息，用打字更正，例如「金額應該是 1200」。只有原上傳者可以更正；可以改票券種類、名稱、日期時間、地點、座位或票種、金額、幣別，也可以說「這不是票券」而撤回這一筆。**票號與「其他資訊」不能用打字更正**（要改請直接編輯 Excel）；回覆結果訊息時如果內容是 `!` 指令，就當成指令執行，不當成更正文字（Excel 該列標記為「已更正移除」，照片保留）。更正後回覆「舊值 → 新值」並附最新累計。
- `!我的票券`：列出自己當月的紀錄（每筆有流水號），並附累計。可加參數指定月份（例如 `!我的票券 2026-09`）或 `全部`。
- `!說明`：回覆指令與功能說明（只說明現有功能；後面不能加內容；與其他指令共用每人每分鐘 8 次的限流）。
- `!刪除 編號`：刪除自己的某一筆。bot 會先請上傳者在 60 秒內回覆確認訊息並輸入「確定」，或直接在同一頻道傳送「確定」，才真的刪；Excel 該列標記為「已刪除」，不實際移除，照片保留。
- 查詢、更正、刪除都只能動自己的紀錄。

## 不需要的
- 註冊、登入
- 長時間、大規模的雲端服務（這就是一支開著才會動的本機程式）
- 匯率換算（改成依幣別分開顯示）
- 每日使用上限（只做每人每分鐘限流）
- 自動刪除使用者在頻道裡傳的原訊息
- 一張照片拆成多筆、PDF 多頁處理、跨使用者的重複判斷（照片雜湊防重也只限同一位上傳者）、相似照片偵測、替舊紀錄補算雜湊
- 失敗時主動通知我（只寫 log）

## 技術上我知道的
- 用 Python 3.12 + uv（課前已經裝好；實務上也可以用別的語言，這裡先固定）
- 照片用 `claude -p` 在我這台電腦上處理
- Discord 用 Gateway（bot）模式，不需要 ngrok
- 紀錄存成一個可以持續往下加的 Excel 檔
- 設定放在 `.env`：`DISCORD_TOKEN`、`CHANNEL_ID`、`CLAUDE_MODEL`、`DATA_DIR`

2. 之後（上課時）再把防護全部關掉做對照
